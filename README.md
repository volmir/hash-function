# SimpleHash

Учебная хеш-функция на PHP с выходом 32 и 128 бит и тестами, которые показывают,
как оценивать детерминизм, лавину, коллизии и распределение. Приоритет проекта —
понятность и наглядность, а не скорость или криптостойкость.

**Не использовать для паролей, подписей и задач безопасности.** Размер выхода
32/128 бит сам по себе не даёт криптостойкости. Константы подобраны вручную
и проверены тестами; математического анализа безопасности не проводилось.

## Запуск через Docker

Нужны Docker и Docker Compose. Из каталога проекта выполните:

```sh
# Все уровни по порядку, seed по умолчанию равен 1
docker compose run --rm app php run.php

# Один уровень с фиксированным seed
docker compose run --rm app php run.php --level=3 --seed=1

# Другая воспроизводимая выборка
docker compose run --rm app php run.php --level=3 --seed=42

# Сравнение с доступными библиотечными хешами
docker compose run --rm app php run.php --level=6 --seed=1

# Проверка самих измерителей на синтетических данных
docker compose run --rm app php tests/check-metrics.php
```

Контейнер использует 64-битный PHP 8.3 CLI (`php:8.3-cli`). При первом запуске
Compose собирает образ и подключает каталог проекта в `/app`. PHP на хосте,
Composer, дополнительные пакеты и внешние сервисы для запуска не нужны.

| Опция | Значение | По умолчанию |
|---|---|---|
| `--level=N` | Один уровень от 1 до 6 | Все уровни по порядку |
| `--seed=N` | Целое число в диапазоне PHP int | `1` |

Seed печатается в выводе. Все случайные данные генерируются через `mt_rand()`
с инициализацией `mt_srand($seed)`. При одинаковом seed в том же окружении
данные совпадают для отдельного и общего запуска уровня.

Код возврата `0` означает, что выбранные проверки прошли, `1` — провал проверки
или исключение, `2` — ошибку аргументов. Неизвестные и повторные опции,
нецелые значения и уровни вне диапазона отклоняются.

## Пример использования

```php
require __DIR__ . '/autoload.php';

use Hash\SimpleHash;

$str = 'Example text';
$simpleHash = new SimpleHash();
echo $simpleHash->get32bit($str) . PHP_EOL;
// c0bd6183
echo $simpleHash->get128bit($str) . PHP_EOL;
// a76e8df2bfabc0aa6d319fbb55403207
```

`get32bit(string): string` возвращает ровно 8 hex-цифр, `get128bit(string): string` —
ровно 32, в нижнем регистре с ведущими нулями. Вход обрабатывается по байтам,
включая нулевые байты и UTF-8.

## Формула хеша

Вход — последовательность байтов `b₀…bₗ₋₁`, `L = strlen(input)`.
Нулевые байты учитываются, UTF-8 не декодируется в символы. Все состояния
неотрицательны и ограничены 32 битами. Ниже приведён псевдокод; операции
выполняются в указанном порядке.

### 32-битный раунд

```text
M = 0xFFFFFFFF
P = 0xA7D46BAD
mul32(a, b) = (a × b) mod 2³²
rotl32(h, k) = ((h << k) & M) | (h >> (32 − k))

R(h, byte):
    h = rotl32(mul32(h XOR byte, P), 13)
    h = h XOR (h >> 15)
    вернуть h
```

`mul32()` реализован через 16-битные половины: прямое произведение двух
32-битных чисел может переполнить PHP int и стать float. Нечётный множитель,
циклический сдвиг и XOR со сдвигом сохраняют обратимость раунда по состоянию
при фиксированном байте. Это свойство раунда не является доказательством
криптостойкости хеша.

### Длина и финализатор

```text
A(h):
    повторить AVALANCHE_ROUNDS раз (по умолчанию 2):
        h = mul32(h XOR (h >> 16), 0xD59B4E93)
        h = mul32(h XOR (h >> 13), 0xA3C79B5D)
    вернуть h

F(h, L) = A(h XOR (L & M))
```

XOR со сдвигом переносит влияние старших битов вниз. Умножение через переносы
распространяет влияние младших битов вверх. Число раундов, сдвиги и собственные
нечётные множители вынесены в константы класса.

Для `get32bit()` начальное состояние `h = 0x73A4D1B7`. Каждый байт последовательно
обрабатывается как `h = R(h, byte)`, затем `h = F(h, L)`. Результат
форматируется через `sprintf('%08x', h)`: ровно 8 hex-цифр нижнего регистра
с сохранением ведущих нулей. Даже пустой вход проходит финализацию.

### 128-битный вариант

Для `get128bit()` используются четыре начальных состояния:

```text
s1 = 0x73A4D1B7
s2 = 0xC5E92F83
s3 = 0x1D8B6A59
s4 = 0xE2F47C31
```

Каждый байт обрабатывается раундом `R` во всех четырёх состояниях. После
последнего байта выполняется перекрёстное смешивание. `add32(a, b)` означает
`(a + b) & M`. Обновления ниже последовательные: следующая строка видит
значения, изменённые предыдущими строками.

```text
s1 = add32(s1, rotl32(s2, 7))
s2 = add32(s2, rotl32(s3, 11))
s3 = add32(s3, rotl32(s4, 17))
s4 = add32(s4, rotl32(s1, 23))

s1 = s1 XOR rotl32(s3, 13)
s2 = s2 XOR rotl32(s4, 19)
s3 = s3 XOR rotl32(s1, 7)
s4 = s4 XOR rotl32(s2, 11)
```

Затем для каждого состояния вычисляется `F(si, L)`. Четыре результата
форматируются через `%08x` и склеиваются в порядке `s1`, `s2`, `s3`, `s4`:
ровно 32 hex-цифры нижнего регистра с ведущими нулями.

## Уровни тестов

Каждый уровень печатает «что проверяем → результат → как читать».

| Уровень | Проверка |
|---|---|
| 1 | Смоук: формат 8/32 hex и 30 эталонных значений |
| 2 | Детерминизм: повторы, новые экземпляры, порядок вызовов и векторы |
| 3 | Лавина: среднее и вероятность изменения каждого бита, отдельно последний байт |
| 4 | Коллизии на случайных и структурных входах рядом с ожидаемым числом |
| 5 | Распределение hex-цифр, битовых позиций и 256 бинов полного диапазона |
| 6 | Сравнительные таблицы тех же измерений для нашей функции и эталонов |

Уровни 1–5 проверяют оба выхода — 32 и 128 бит. Уровень 6 сравнивает
32-битные выходы нашей функции и эталонов.

Уровень 2 использует 15 векторов и 128 случайных входов. Для каждого выхода
делает по пять повторов на том же экземпляре и на новых, затем обходит входы
в обратном и перемешанном порядке, меняя также порядок вызовов методов.
Все 3462 сравнения должны совпасть.

### Лавина

Для каждого выхода и каждого из двух сценариев используется 5000 входов
длиной 1–64 байта. Переворачивается ровно один случайный бит: сначала
в произвольном байте, отдельно — в последнем. «Последний символ» означает
последний **байт**, поскольку алгоритм работает по байтам, включая UTF-8.
Печатаются средняя доля изменившихся битов и min/max вероятности изменения
среди всех выходных позиций. Идеал — среднее 50% и вероятность 0,50 у каждого
бита; учебная норма — все эти величины в пределах 0,45–0,55. Одного среднего
для успеха недостаточно.

Меняя `SimpleHash::AVALANCHE_ROUNDS` или константы, запускайте уровень 3
с тем же seed. Уровни 1–2 при изменении хешей потребуют осознанного пересмотра
векторов. `tests/Metrics.php` содержит общий код измерений без готовых хеш-функций.

### Коллизии

`tests/DataSets.php` генерирует уникальные входы, не сохраняя весь набор в памяти.
В множестве хешей проверка повторов выполняется через `isset`.

| Набор | Число входов | Построение |
|---|---:|---|
| Случайные строки | 1000000 | 8 случайных байтов + 4 байта уникального индекса |
| Последовательные числа | 1000001 | Строки `0`…`1000000` включительно |
| Повторы одного символа | 2048 | `a`, `aa`, …, строка из 2048 букв `a` |
| Перестановки | 1000000 | Первые лексикографические перестановки десяти разных букв `abcdefghij` |
| Нулевые байты | 1000000 | Четырёхбайтный индекс в сетевом порядке + `\0` |

Число коллизий — число повторных выходов, то есть `n − число уникальных хешей`.
Рядом всегда печатается приближённое ожидание `n² / (2 × 2^bits)` и верхний
ориентир `2 × ожидание + 5`. Для миллиона входов и 32 бит ожидание ≈116,42.
Малый набор повторов символа оставлен структурной проверкой: миллион разных
длин потребовал бы обработки около 500 миллиардов байт. Его малое ожидание
(≈0,00049 для 32 бит), как и отсутствие коллизий на 128 битах, не доказывает
качество или криптостойкость.

### Распределение

На 100000 тех же уникальных случайных входов считаются частоты hex-цифр
(идеал 6,25%), частоты по каждой hex-позиции и вероятность единицы в каждой
битовой позиции (идеал 0,50). Нумерация битов: байты слева направо, внутри
байта — от младшего бита к старшему.

256 бинов по старшему байту покрывают весь диапазон `0x00000000…0xFFFFFFFF`:
ноль входит в первый бин, максимум — в последний. Для 128 бит измеряется
каждая 32-битная часть и их общая гистограмма.

Используется `χ² = Σ (наблюдаемое − ожидаемое)² / ожидаемое`. Печатаются
χ² hex-цифр и худшей hex-позиции (15 степеней свободы), сумма χ² битов
(32/128), худший бит (1), χ² бинов и худшей 32-битной части (255).
Все статистики должны быть не выше `df + 6√(2df) + 18`; это консервативный
учебный ориентир, **не точный квантиль и не p-value**. Метрики исследуют
частоты, но не все корреляции и зависимости между битами.

Уровень 5 выводит текстовые таблицы с рамками: частоты hex-цифр, вероятности
единицы по битам и критерии χ² с порогами и оценками. В таблице битов каждая
строка соответствует одному байту, столбцы `+0`…`+7` задают смещение от первого
номера бита в строке. Числа выровнены по правому краю, подписи — по левому.

### Сравнение

Уровень 6 запускает тот же код уровней 3–5 на одинаковых данных для
`SimpleHash::get32bit()`,
`crc32b`, `fnv1a32`, `murmur3a`, `xxh32`, `md5` и `sha256` через `hash()`.
Каждый эталон использует первые 8 hex-цифр (32 бита). Недоступные в `hash_algos()` эталоны пропускаются с сообщением.

Уровень 6 выводит отдельные текстовые таблицы с рамками для обоих сценариев
лавины, коллизий, распределения χ² и итоговых оценок. Коллизии и ожидание
стоят рядом, для каждого набора указаны число входов и порог. Пороги χ²
приведены в отдельной строке таблицы распределения.
Ожидаемая слабость эталона сама по себе
не делает запуск неуспешным: код уровня 6 определяется тремя измерениями
нашей 32-битной функции. Таблицы не являются рейтингом криптостойкости.

Полный запуск обрабатывает миллионы входов и может занять несколько минут.
Измерения нашей 32-битной функции из уровней 3–5 повторно используются
в уровне 6; полный набор входов в памяти не хранится.

`tests/check-metrics.php` отдельно проверяет измеритель на синтетических
выходах с известными частотами и коллизиями, границы бинов, воспроизводимость
и уникальность входов. Есть случай с идеальным средним лавины 50%, но
вероятностями отдельных битов 0 и 1: он обязан получить оценку «плохо».

## Самостоятельный алгоритм и библиотечные эталоны

**Сам алгоритм `get32bit()` / `get128bit()` не использует внешних хеш-функций.**
В нём нет вызовов `hash()`, `crc32()`, `md5()` или `sha1()`, готовых финализаторов
и заимствованных констант известных хешей. Он собран из собственных раундов,
побитовых операций и целочисленной арифметики.

Библиотечные хеши нужны **только тесту сравнения — уровню 6**. Они вызываются
в `tests/Runner.php` как точки отсчёта для тех же измерений лавины, коллизий
и распределения. Для полноты набора эталонов желателен **PHP ≥ 8.1**;
контейнер проекта использует PHP 8.3. Доступность каждого алгоритма проверяется
через `hash_algos()`: отсутствие эталона приводит к сообщению о пропуске,
а не к падению теста. Это не зависимость реализации `SimpleHash`.

## Эталонные векторы

`tests/vectors.php` хранит 15 входов и 30 буквальных ожидаемых хешей: пустая
строка, ASCII, UTF-8, нулевые и старшие байты, длинная строка, выходы с ведущими
нулями. Уровень 1 проверяет формат и значения, уровень 2 — значения и детерминизм.
При несовпадении выводятся ожидаемый и полученный хеши; запуск возвращает код `1`.

При любом намеренном изменении алгоритма, включая число раундов финализатора,

## Ограничения

Результаты короткой практической проверки приведены в
[оценке криптостойкости](docs/security-review.md): найден целевой второй прообраз
для 32 бит и подтверждено предсказание продолжения для обоих вариантов.
Показана подделка тега в схеме `H(secret || message)` при известной общей длине.
Коллизии и прообразы полного 128-битного выхода в этой проверке не искались.

Функция учебная: **не использовать для хранения паролей, подписей и любых
задач безопасности**. Имя `SimpleHash` означает «простой учебный хеш», он не предназначен для безопасности.
Ни 32-битный, ни 128-битный выход сам по себе её не даёт.

Константы подобраны вручную и проверены тестами. Математического анализа
стойкости к намеренному поиску коллизий, прообразов и другим атакам нет.
Детерминизм, хорошая лавина, равномерные частоты и отсутствие найденных коллизий
на конечных наборах не заменяют такой анализ.

Реализация рассчитана на **64-битный PHP**; состояние держится неотрицательным,
умножение выполняется без перехода во float. Длина учитывается по модулю 2³².
Тесты статистические и зависят от набора данных и seed. Пороги χ² учебные;
проверяемые частоты не охватывают все возможные зависимости между битами.
