Формат (его читает `orchestrator/run.sh`, менять структуру не нужно):

## P6: Односторонний финал: обратная связь в обеих функциях (алгоритм)
tier: heavy
gate: php -r 'require "autoload.php"; $h = new Hash\SimpleHash(); foreach (["", "a", "Example text"] as $s) { if (!preg_match("/^[0-9a-f]{8}$/", $h->get32bit($s)) || !preg_match("/^[0-9a-f]{32}$/", $h->get128bit($s))) { exit(1); } }'
```prompt
Добавь в `Hash\SimpleHash` односторонний финал по схеме «выход = финал(S) ^ S» для ОБЕИХ функций. Раунд `round()` и поглощение байтов НЕ менять (раунд остаётся биективным). Новых констант не нужно.
ПЕРЕД правкой запусти `docker compose run --rm app php run.php --level=3`, `--level=4`, `--level=5`, `--level=6` и сохрани вывод во временный файл вне репозитория (например /tmp/levels-before.txt) для сравнения «до/после» в следующих шагах.
Реализация:
1) Раздели финал на две части: метод `mixFinal(int $state, int $length)` = `avalanche($state ^ ($length & MASK32))` (без обратной связи) и новый атомарный метод `feedForward(int $mixed, int $original)` = `$mixed ^ $original`, с комментарием: это единственное место, где информация теряется намеренно; XOR возвращает в результат исходное состояние, поэтому равенство «выход = f(x) ^ x» нельзя решить обратными операциями; делаем один раз в конце, а не в каждом раунде, иначе раунд перестанет быть биективным.
2) `get32bit()`: `y = state ^ (length & MASK32)`; выход = `feedForward(avalanche(y), y)`.
3) `get128bit()`: сохрани копии состояний дорожек ПОСЛЕ поглощения и ДО перекрёстного смешивания (`S1..S4`); перекрёстное смешивание оставь как есть; затем для каждой дорожки `T_k = mixFinal(M_k, length)` (M_k — дорожка после смешивания) и выход дорожки `feedForward(T_k, S_k)`. ВАЖНО: обратную связь делай именно с состоянием до смешивания, а не с самой дорожкой после смешивания: иначе дорожки решаются независимо друг от друга (около 2^34 работы вместо ~2^128). Объясни это в комментарии.
4) Формат вывода (8 и 32 hex-цифры, нижний регистр, ведущие нули) не меняется.
5) Обнови формулу и описание алгоритма в `README.md` и инварианты в `AGENTS.md` (раздел 3: финал односторонний за счёт обратной связи по состоянию; раунд по-прежнему биективен; для 128 бит обратная связь берётся до смешивания дорожек; добавь в ловушки: не применять обратную связь к каждой дорожке отдельно).
6) `tests/vectors.php` и тесты на эталонные значения НЕ трогай: хеши изменились, поэтому проверки по векторам и `check-cli` ожидаемо упадут. В ответе покажи, что падают только значения хешей, а длина и формат вывода верны (`php -r` с несколькими примерами).
```

## P11: Шаг 3 «что обратимо внутри и где обратимость обрывается»

```prompt
Добавь шаг 3. Внутренности `SimpleHash` закрыты (private), поэтому создай в `security/`:
```
