# AGENTS.md

Инструкции для AI-агентов, работающих с проектом. Читай целиком перед первой правкой.

Общайся с пользователем на русском языке.

## 1. Что это за проект

Учебная хеш-функция `Hash\SimpleHash` на PHP: 32-битный (`get32bit()`) и 128-битный (`get128bit()`) варианты. Уже реализованы Docker, автозагрузка, эталонные векторы, уровни тестов 1–6, проверки измерителей и документация по ограничениям.

Главный приоритет: **понятность и наглядность**, а не производительность и не криптостойкость.

## 2. Правила проекта (нарушать нельзя)

- **Не усложнять.** Учебный проект: если есть простой вариант, выбирай его. Не добавлять фреймворки, Composer-зависимости, паттерны «на вырост».
- **Автономность алгоритма.** В `get32bit()` / `get128bit()` и их вспомогательных методах только базовые конструкции языка (`^ & | << >> + *`, `sprintf`, `ord`, `strlen`, циклы). Никаких `hash()`, `crc32()`, `md5()`, `sha1()`, готовых финализаторов и констант известных хешей (MurmurHash3, FNV, xxHash). Константы придумываются свои; множители — нечётные 32-битные числа.
- **Библиотечные хеши** (`crc32b`, `fnv1a32`, `murmur3a`, `xxh32`, `md5`, `sha256`) допустимы **только** в тестах сравнения как эталоны; если алгоритма нет в `hash_algos()`, пропускать его с сообщением.
- **Старый алгоритм заменён полностью.** Версии `LegacyHash` нет и не нужно.
- **Публичный API:** `get32bit(string): string` (ровно 8 hex-символов) и `get128bit(string): string` (ровно 32). Нижний регистр, ведущие нули сохраняются, формат `sprintf('%08x')`. Не менять без явной просьбы.
- **Язык:** комментарии, вывод тестов и README на русском, идентификаторы английские.

## 3. Текущая архитектура и инварианты алгоритма

Инварианты, которые нужно сохранять при любых правках:

1. **Раунд биективен по состоянию при фиксированном байте.** `absorbByte()` подмешивает байт через XOR; `round()` умножает через `mul32()` на `0xA7D46BAD`, вращает на 13 бит и выполняет `h ^= h >> 15`. Нельзя заменять вращение сдвигом с потерей бита, вводить десятичные преобразования, паддинг, деление или `%`. Маска для арифметики mod 2³² допустима и необходима; она не исправляет переполнение PHP int во float.
2. **Длина входа в байтах по модулю 2³² подмешивается XOR** в `finalize()` до финализатора, включая пустой вход.
3. **Финализатор `avalanche()`** собственный: `AVALANCHE_ROUNDS = 2`, в каждом раунде две пары «XOR со сдвигом + `mul32()`» со сдвигами `[16, 13]` и множителями `[0xD59B4E93, 0xA3C79B5D]`. Параметры вынесены в константы класса. Их изменение меняет хеши.
4. **128 бит** = четыре 32-битных состояния с разными началами из `INITIAL_STATES`; каждый байт обрабатывается во всех четырёх. Перед финалом выполняются сложения mod 2³² и XOR с вращениями соседних состояний. Обновления последовательные: порядок строк значим. Каждая часть проходит `finalize()`, затем четыре `%08x` склеиваются в порядке состояний.
5. Алгоритм собран из **атомарных методов** (`initState`, `rotl32`, `mul32`, `absorbByte`, `round`, `avalanche`, `finalize`, `toHex`): один метод, одна задача, комментарий «что и зачем».

## 4. Ловушки PHP (проверяй, прежде чем писать арифметику)

- Реализация требует **64-битный PHP**; Docker использует `php:8.3-cli`. Уровень 1 проверяет `PHP_INT_SIZE`.
- **Прямое `uint32 * uint32` может превысить `PHP_INT_MAX` (2⁶³−1) и тихо стать float.** Умножение только через `mul32()` с разбиением первого множителя на 16-битные половины. В текущей реализации промежуточные произведения меньше 2⁴⁸, остаются int, младшая и старшая части маскируются до сложения.
- Результаты `+`, `<<`, `*`, способные выйти за 32 бита, ограничивать маской `& 0xFFFFFFFF`; промежуточные вычисления должны помещаться в PHP int. Сложение и умножение mod 2³² — часть алгоритма, а не случайное усечение.
- `>>` в PHP арифметический для отрицательных чисел. Состояние держать неотрицательным (всегда маскировать).
- Оператор `/` возвращает float; в PHP ≥ 8.1 неявное float→int с потерей точности даёт Deprecated. Деления в алгоритме быть не должно.
- `^` между двумя строками работает побайтово. В алгоритме XOR применяется к целым состояниям и значениям `ord()`; в `tests/Metrics.php` XOR двоичных строк намеренно используется для сравнения выходов.
- Хеш считается по **байтам** (`strlen`, `ord`), а не по символам; юникод обрабатывается как последовательность байт.

## 5. Структура и запуск

Фактическая структура:

```
src/SimpleHash.php          # алгоритм
src/Data/EnglishWords.php   # словарь уникальных слов
src/Data/IpAddress.php      # демонстрационные IPv4-адреса
src/Data/Passwords.php      # демонстрационные строки, похожие на пароли
tests/Runner.php           # CLI, уровни 1–6, текстовые таблицы результатов
tests/Metrics.php          # общие измерения лавины, коллизий и распределения
tests/DataSets.php         # воспроизводимые уникальные входы для измерений
tests/vectors.php          # 15 входов, 30 буквальных ожидаемых хешей
tests/check-metrics.php    # отдельные проверки самих измерителей
autoload.php               # Hash\ → src/, Tests\ → tests/, без Composer
run.php                    # точка входа: Tests\Runner
Dockerfile, docker-compose.yml, .dockerignore
README.md                  # запуск, формулы, тесты, ограничения
docs/security-review.md    # результаты практической проверки криптостойкости
```

Утилиты `Hash\Data\*` — классы со статическим `get()`, без глобальных функций. Уровни 2–6 получают тестовые входы из `Tests\DataSets`; демонстрационные утилиты не заменяют эти наборы.

Запуск **только через Docker** (PHP на хосте может отсутствовать или быть другой версии):

```
docker compose run --rm app php run.php                     # все уровни, seed=1
docker compose run --rm app php run.php --level=3 --seed=1  # один уровень
docker compose run --rm app php tests/check-metrics.php     # проверки измерителей
```

Compose собирает сервис `app` и подключает каталог проекта в `/app`. Полный прогон обрабатывает миллионы входов и может занять несколько минут.

`--level` принимает одно число 1–6; запись `--level=1..4` не поддерживается. `--seed` — целое в диапазоне PHP int, по умолчанию `1`. Неизвестные и повторные опции отклоняются. Коды возврата: `0` — проверки прошли, `1` — провал проверки или исключение, `2` — ошибка аргументов.

Если Docker недоступен, **не утверждай, что тесты прошли**: укажи причину и команду для проверки. Запуск PHP на хосте не заменяет проверку в Docker.

## 6. Тесты: что считать правильным

Уровни идут от простого к сложному. Каждый печатает «что проверяем → результат → как читать».

| Уровень | Что проверяет |
|---|---|
| 1 | Формат обоих выходов и 30 значений из 15 векторов |
| 2 | Детерминизм обоих выходов: векторы, 128 случайных входов, повторы, новые экземпляры, порядок вызовов; всего 3462 сравнения |
| 3 | Лавину обоих выходов: отдельно произвольный и последний байт |
| 4 | Коллизии обоих выходов на уникальных случайных и структурных входах |
| 5 | Распределение обоих выходов: hex-цифры, позиции, биты и бины |
| 6 | Сравнение 32-битных выходов нашей функции и библиотечных эталонов |

- **Воспроизводимость:** случайность в тестах через `mt_rand()` с `mt_srand($seed)`; seed печатается. Данные должны совпадать при отдельном и общем запуске уровня с тем же seed. Не использовать `str_shuffle()` для воспроизводимых выборок; в уровне 2 порядок перемешивается через `mt_rand()`.
- **Лавина:** по 5000 входов длиной 1–64 байта на сценарий, переворот ровно одного входного бита. Проверять среднее (идеал 50%) **и все выходные биты** (min/max вероятности изменения, идеал 0,50). Норма: среднее и все вероятности 0,45–0,55 при ≥ 5000 выборок. Одного среднего недостаточно; метрику «% совпавших hex-символов» не использовать.
- **Коллизии:** считать повторные выходы на уникальных входах, всегда печатать число коллизий **рядом с ожидаемым** `n² / (2 · 2^bits)`; допустимо ≤ `2 · ожидание + 5`. Текущие наборы: 1 000 000 случайных строк (8 случайных байтов + 4 байта индекса), 1 000 001 число от 0 до 1 000 000, 1 000 000 перестановок `abcdefghij`, 1 000 000 бинарных строк с `\0`. Повторы `a` ограничены длинами 1–2048: миллион длин потребовал бы около 500 млрд байт обработки. Малое ожидание, особенно для 128 бит, ничего не доказывает.
- **Распределение:** 100 000 уникальных случайных входов; частоты hex-цифр в целом и по позициям, вероятность единицы в каждом бите, 256 бинов по старшему байту полного диапазона 0…2³²−1. Для 128 бит проверять каждую 32-битную часть и общую гистограмму. Порог χ²: `df + 6√(2df) + 18` — учебный ориентир, не точный квантиль и не p-value.
- **Сравнение:** использовать общий код `Metrics` и одинаковые данные для всех функций. Библиотечные эталоны берутся по первым 8 hex-цифрам. Провал эталона не делает уровень 6 неуспешным: его код определяется результатами `SimpleHash32`. `Runner` повторно использует измерения нашей функции из уровней 3–5.
- **Измерители:** `tests/check-metrics.php` отдельно проверяет формулы, границы бинов, уникальность и воспроизводимость входов. Синтетический случай со средним лавины 50%, но вероятностями битов 0 и 1, обязан проваливать критерий лавины.
- **Векторы (`tests/vectors.php`):** обновлять осознанно и только после намеренного изменения алгоритма; нельзя править их, чтобы тест позеленел. В описании коммита или ответа указывать, почему алгоритм изменён.
- Для структур данных проверки на дубликаты через `isset`, не `in_array` (O(n²)). Миллионные входы генерировать потоком; не хранить весь набор строк в памяти.

Не ослаблять пороги и не уменьшать выборки ради прохождения тестов. Сравнивать изменения на одинаковых данных с фиксированным seed.

## 7. Как работать (быстро, без потери качества)

- **Одна задача = одна связная правка.** Не смешивать посторонний рефакторинг со сменой алгоритма или тестов. Этапы первоначальной сборки уже завершены; не создавать параллельные реализации.
- Перед правкой алгоритма прочитать `src/SimpleHash.php`, `tests/vectors.php` и формулы в README. Если затронуты выводы о безопасности, также прочитать `docs/security-review.md`.
- Если правка меняет хеши, **сразу** сообщить об этом. Пересмотреть векторы отдельным осознанным шагом и объяснить причину изменения алгоритма; обновить примеры и формулы в README. Проверить актуальность конкретных примеров в `docs/security-review.md`.
- После изменения алгоритма проверить уровни 1–4, затем 5–6. Полный запуск `docker compose run --rm app php run.php --seed=1` выполняет их в нужном порядке.
- При изменении `Metrics` / `DataSets` запустить `tests/check-metrics.php` и затронутые уровни 2–6; при изменении CLI / автозагрузки / Docker проверить запуск, уровни 1–2 и затронутые варианты аргументов. Выбирать проверки по области изменения.
- Для правок только документации сверить пути, команды и утверждения с кодом. Полный статистический прогон не обязателен; примеры запуска проверять, если они изменились.
- Менять только то, что относится к задаче. Не переименовывать, не форматировать чужие файлы «заодно».
- Не писать комментарии ради комментариев, но у каждого атомарного метода должно быть понятно **зачем он** (это учебная ценность).
- Не вводить новые зависимости и новые уровни абстракции без явной просьбы. Сомневаешься, спроси одним коротким вопросом.

## 8. Definition of Done для любой задачи

- Для изменений кода тесты нужных уровней запущены через Docker, результаты приведены в ответе (числа, а не «всё ок»). Для документации проверено соответствие текущему проекту; если тесты не запускались, это сказано явно.
- Публичный API и формат вывода (8/32 hex) не сломаны.
- Нет нарушений разделов 2–4.
- README обновлён, если изменились алгоритм, запуск, тесты или ограничения. AGENTS.md и `docs/security-review.md` согласованы с затронутыми изменениями.
- В ответе: что изменено, что проверено, что **не** проверено.

## 9. Ограничения проекта (для README и ответов)

Функция учебная: не использовать для паролей, подписей и безопасности. 32/128 бит выхода не дают криптостойкости; константы подобраны вручную и проверены статистически. Полного математического анализа стойкости нет.

В `docs/security-review.md` зафиксированы целевой второй прообраз для 32 бит и предсказание продолжения для обоих вариантов. Показана подделка тега `H(secret || message)` при известной общей длине. Коллизии и прообразы полного 128-битного выхода в этой проверке не искались. Не выдавать успешные статистические тесты за опровержение этих результатов или доказательство безопасности.
