# AGENTS.md

Инструкции для AI-агентов, работающих с проектом. Читай целиком перед первой правкой; файл короткий намеренно.

## 1. Что это за проект

Учебная хеш-функция на PHP (`SimpleCryptoHash`): 32-битный (`get()`) и 128-битный (`get128bit()`) варианты, плюс тестовая инфраструктура, которая **объясняет**, как оценивать качество хеша (детерминизм → лавина → коллизии → распределение → сравнение с промышленными хешами).

Главный приоритет: **понятность и наглядность**, а не производительность и не криптостойкость.

## 2. Правила проекта (нарушать нельзя)

- **Не усложнять.** Учебный проект: если есть простой вариант, выбирай его. Не добавлять фреймворки, Composer-зависимости, паттерны «на вырост».
- **Автономность алгоритма.** В самой функции только базовые конструкции языка (`^ & | << >> + *`, `sprintf`, `ord`, `strlen`, циклы). Никаких `hash()`, `crc32()`, `md5()`, `sha1()`, готовых финализаторов и констант известных хешей (MurmurHash3, FNV, xxHash). Константы придумываются свои (нечётные 32-битные числа).
- **Библиотечные хеши** (`crc32b`, `fnv1a32`, `murmur3a`, `xxh32`, `md5`, `sha256`) допустимы **только** в тестах сравнения как эталоны; если алгоритма нет в `hash_algos()`, пропускать его с сообщением.
- **Старый алгоритм заменён полностью.** Версии `LegacyHash` нет и не нужно. `getStringSum` остаётся как учебный антипример, не как реализация для развития.
- **Публичный API:** `get(string): string` (ровно 8 hex-символов) и `get128bit(string): string` (ровно 32). Нижний регистр, ведущие нули сохраняются, формат `sprintf('%08x')`. Не менять без явной просьбы.
- **Язык:** комментарии, вывод тестов и README на русском, идентификаторы английские.

## 3. Целевая архитектура алгоритма

Инварианты, которые нужно сохранять при любых правках:

1. **Раунд биективен** (не теряет информацию): XOR, умножение на нечётную константу mod 2³², циклический сдвиг, `h ^= h >> k`. Нельзя вводить `>> 1` с потерей бита, `strrev` по десятичной записи, паддинг через `sprintf`, деление, `%`, обрезку маской после операции, которая вышла за 32 бита.
2. **Длина входа подмешивается** в финальное состояние (XOR) до финализатора.
3. **Финализатор `avalanche()`** собственный: повторы пары «`h ^= h >> k`» и «`h = mul32(h, ODD_CONST)`». Число раундов и константы вынесены в константы класса.
4. **128 бит** = четыре 32-битных состояния с разными начальными константами, перекрёстное перемешивание перед финалом, каждое состояние проходит `avalanche()`.
5. Алгоритм собран из **атомарных методов** (`initState`, `rotl32`, `mul32`, `absorbByte`, `round`, `avalanche`, `finalize`, `toHex`): один метод, одна задача, комментарий «что и зачем».

## 4. Ловушки PHP (проверяй, прежде чем писать арифметику)

- **`uint32 * uint32` переполняет `PHP_INT_MAX` (2⁶³) и тихо становится float.** Умножение только через `mul32()` с разбиением на 16-битные половины: `(((a & 0xFFFF) * b) + ((((a >> 16) * b) & 0xFFFF) << 16)) & 0xFFFFFFFF`.
- После каждой арифметической операции, способной выйти за 32 бита (`+`, `<<`, `*`), применять `& 0xFFFFFFFF`.
- `>>` в PHP арифметический для отрицательных чисел. Состояние держать неотрицательным (всегда маскировать).
- Оператор `/` возвращает float; в PHP ≥ 8.1 неявное float→int с потерей точности даёт Deprecated. Деления в алгоритме быть не должно.
- `^` между двумя строками работает побайтово, а не как число. Приводить строки к int явно.
- Хеш считается по **байтам** (`strlen`, `ord`), а не по символам; юникод обрабатывается как последовательность байт.

## 5. Структура и запуск

Целевая структура (если чего-то ещё нет, значит соответствующий шаг серии промптов не выполнен; не создавай заранее):

```
src/SimpleCryptoHash.php    # алгоритм
src/...                     # утилиты данных (пароли, слова, IP) без глобальных функций
tests/Runner.php            # запуск уровней
tests/vectors.php           # эталонные векторы нового алгоритма
run.php                     # точка входа
Dockerfile, docker-compose.yml
README.md
```

Запуск **только через Docker** (PHP на хосте может отсутствовать или быть другой версии):

```
docker compose run --rm app php run.php                    # все уровни
docker compose run --rm app php run.php --level=3 --seed=1 # один уровень, фиксированный seed
```

Если Docker недоступен и PHP не установлен, **не утверждай, что тесты прошли**: скажи, что не смог запустить, и опиши, как проверить.

## 6. Тесты: что считать правильным

Уровни идут от простого к сложному: 1 смоук → 2 детерминизм → 3 лавина → 4 коллизии → 5 распределение → 6 сравнение. Каждый уровень печатает «что проверяем → результат → как читать». Код возврата ≠ 0 при провале.

- **Воспроизводимость:** любая случайность через `mt_srand($seed)`, seed печатается в выводе.
- **Лавина:** переворот 1 бита входа; смотреть среднее (идеал 50%) **и худший выходной бит** (min/max вероятности изменения, идеал ≈ 0,50 у всех; ориентир «норма» 0,45–0,55 при ≥ 5000 выборок). Одного среднего недостаточно: оно скрывает слабые биты. Метрику «% совпавших hex-символов» не использовать.
- **Коллизии:** всегда печатать число коллизий **рядом с ожидаемым** по парадоксу дней рождения (`n² / 2 / 2^bits`). Для 32 бит и 10⁴ элементов ожидание ≈ 0,01, и такой тест ничего не доказывает, нужны наборы ≥ 10⁶ и структурные входы (последовательные числа, повторы символа, перестановки, `\0`). Допустимо ≤ ~2× ожидаемого + 5.
- **Распределение:** бины покрывают полный диапазон 0…2³²−1; χ² к равномерному.
- **Векторы (`tests/vectors.php`):** обновлять осознанно и только после намеренного изменения алгоритма; нельзя править их, чтобы тест позеленел. В описании коммита или ответа указывать, почему алгоритм изменён.
- Для структур данных проверки на дубликаты через `isset`, не `in_array` (O(n²)).

Референсные замеры (для оценки «стало лучше или хуже»; получены на прототипе): без финализатора худший выходной бит при изменении последнего символа менялся с вероятностью 0,14…0,63, с финализатором 0,49…0,52; раунд «умножение + сдвиг» без `h ^= h >> 15` давал ~3× больше коллизий на последовательных числах, чем идеал.

## 7. Как работать (быстро, без потери качества)

- **Один шаг серии промптов = одна атомарная правка.** Не соединять рефакторинг, смену алгоритма и тесты в один заход.
- Порядок: Docker → автозагрузка → класс и раунд → длина и финализатор → 128 бит → векторы → каркас тестов → уровни → сравнение → README.
- Перед правкой алгоритма: прочитать `SimpleCryptoHash.php` и `tests/vectors.php`. После правки: прогнать `--level=1..4`, затем остальные.
- Если правка меняет хеши, **сразу** сообщить об этом и пересобрать векторы отдельным шагом, а не молча.
- Менять только то, что относится к задаче. Не переименовывать, не форматировать чужие файлы «заодно».
- Не писать комментарии ради комментариев, но у каждого атомарного метода должно быть понятно **зачем он** (это учебная ценность).
- Не вводить новые зависимости и новые уровни абстракции без явной просьбы. Сомневаешься, спроси одним коротким вопросом.

## 8. Definition of Done для любой задачи

- Тесты нужных уровней запущены через Docker, результаты приведены в ответе (числа, а не «всё ок»).
- Публичный API и формат вывода (8/32 hex) не сломаны.
- Нет нарушений разделов 2–4.
- README обновлён, если изменился запуск, тесты или ограничения.
- В ответе: что изменено, что проверено, что **не** проверено.

## 9. Ограничения проекта (для README и ответов)

Функция учебная: не использовать для паролей, подписей и безопасности. 32/128 бит выхода не дают криптостойкости; константы подобраны вручную и проверены тестами, а не математическим анализом.
